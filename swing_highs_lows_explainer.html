How Swing Highs & Lows Are Determined
ZigZag algorithm on 1h candles (last 200) → structure trend → Fib 74.5% retracement entry
src/indicators/local_indicators.py · zigzag() + zz_structure()
Algorithm
ZigZag Pivot Detection
HIGH MODE
Update to highest bar.high
Confirm when:
bar.low ≤ peak × (1−dev)
LOW MODE
Update to lowest bar.low
Confirm when:
bar.high ≥ trough × (1+dev)
The last pivot is always "forming" (unconfirmed) and is excluded from structure analysis by zz_structure().
Trend Classification → Bias → Entry Gate
HH_HL → bias = "bull"
Last 3 confirmed HIGHs ascending ↗
AND last 3 confirmed LOWs ascending ↗
H₁ < H₂ < H₃ && L₁ < L₂ < L₃
LH_LL → bias = "bear"
Last 3 confirmed HIGHs descending ↘
AND last 3 confirmed LOWs descending ↘
H₁ > H₂ > H₃ && L₁ > L₂ > L₃
mixed → bias = null
HIGHs and LOWs disagree in direction
e.g. HH but LL — choppy / indecisive
swing_count — consecutive confirming pairs from the end
Code (main.py:1113–1117):
if trend == "HH_HL" and swing_count ≥ 2:
bias_dir = "bull"
elif trend == "LH_LL" and swing_count ≥ 2:
bias_dir = "bear"
else: bias_dir = None ← no entry allowed
⚑ swing_count < 2 = bias stays null even if trend is HH_HL or LH_LL.
Both SOL and ETH are currently blocked by this rule.
